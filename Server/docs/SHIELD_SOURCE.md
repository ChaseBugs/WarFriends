# Shield source and lifecycle boundary

`Shield` in the recovered 1.4.0 Client initializes its maximum HP through `IGameController.GetShieldHP(player)`, which reads the player's zero-based `Google2u.BalanceTable` row. The 44 recovered rows range from 560 to 4,626 HP. The `CoverNode.shieldBaseHealth` value of 1,000 is serialized map setup, not the live rank-authorized HP. Player-weapon `Shield.DoDamage` multiplies incoming shot damage by that weapon's `Google2u.WeaponUpgrades.DAMAGETOSHIELD`; all 66 recovered rows currently contain 1.0. The source constants are `ShieldRepairTime=6` seconds, `ShieldRespawnRatePerSec=0.3` of max HP, and `RepairShields=1`.

`ShieldSourceCatalog` validates these complete tables and constants against the pinned battle-content revision before match allocation. `ShieldLifecycle` is a host-only kernel: an allocator-proven level selects max HP; a shot reduces current HP; depletion disables collision; auto repair restores full HP after six seconds; and partial regeneration occurs only with a player, the `canRegenerate` gate and auto repair enabled. It advances on consecutive 30 Hz host ticks. Tests cover damage, the repair boundary, disabled auto repair, regeneration gates and invalid rank/damage/time.

The recovered `GameControllerDeathMatch` calls `MatchManager.StartOverTime` when its clock reaches zero. That method disables shield auto repair and destroys shields when the pinned `DestroyShieldsInOverTime` constant is positive; the 1.4.0 artifact records 1. The live rifle/shotgun host now does the same at its allocator-provided duration: it keeps phase `Running`, clears the scheduled `EndTick` to zero for reconnect projection, emits one `OvertimeStarted` event followed by the shield destruction events, and does not invent an overtime duration. Prototype mode retains its unscored duration-limit abort. The engine and two authenticated UDP peers replay the same overtime/shield sequence; normal Client overtime UI and other mode rules still need integration.

Every exported cover has a source hierarchy path and one active `riot_shield` collider whose `dynamicOwner` equals that path plus `/riot_shield`. `RecoveredBattleMap` now validates this one-to-one binding across all five maps. Its raycast can omit an explicitly disabled dynamic owner, and `ShotCollisionWorld` retains that owner on a hit. A City shotgun-ray test verifies that the initially hit defender shield has the expected cover identity and that filtering only that owner changes the collision result.

Live rifle and shotgun matches now opt in when both signed manifest participants supply a valid zero-based `ShieldLevel`. The host creates eight rank-authored shields from the exact cover hierarchy paths, applies confirmed projectile damage to the opposing shield, suppresses only its collider while down, and advances its six-second repair on the fixed host tick. Snapshots include all eight health/down/revision rows; ordered events report damage, destruction and repair. An in-process City match proves a shotgun breaks a shield, then reaches its owner while the collider is down, and sees the repaired collider return. A two-peer signed UDP match proves both peers receive the same shield damage event. Legacy manifests without levels retain their existing collision behavior.

The Backend allocator still must prove the players' levels and ownership before signing those fields. The exported child trap colliders are inactive, so the source's main `Shield.mCollider.enabled` toggle currently corresponds to one active collider per cover; card activation could change that assumption and needs separate treatment. Regeneration timing uses the host's fixed tick as a reconstruction of the Client's `Time.deltaTime`; it needs a Unity timing comparison before exact parity is claimed. The recovered Client also allows card-controlled repair and regeneration flags, which are not admitted by a player packet here.
