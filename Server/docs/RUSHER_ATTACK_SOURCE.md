# Rusher attack contract (recovered 1.4.0 Client)

Source: `Clients/ExportedProject/Assets/Scripts/Assembly-CSharp/EnemyController.cs`, `SoldierBehaviourRusher.cs`, `SoldierBehaviour.cs`, `SoldierBehaviourDefinititon.cs`, `SoldierAnimationController.cs`, and the referenced legacy animation clips. This is the B14 Rusher attack contract and records the current verified host boundary.

1. `SwitchStateToRusher` stops the agent, begins a 0.5-second point-position tween, and sets `mNextShootTime = mTime + 0.5f`. `RusherUpdate` uses the strict `mTime > mNextShootTime` comparison. The host's `ArmyRusherArrivalState.InitialShotDelayElapsed` already models that first strict boundary; arrival alone never authorizes a shot.
2. An attempt requires `!mWillShoot` and a non-null player at the Rusher point's shield. `PrepareToShoot(true, false, 0f)` also requires `mCanShoot`. It calls `SoldierBehaviourRusher.PickRusherTarget`, which selects the nearest `Moving` target from that player; there is no line-of-sight or maximum-distance gate in this call. The host's `RusherInitialShotTarget` projects the first eligible target, but does not yet model `mWillShoot`, `mCanShoot`, or a shot.
3. `SoldierBehaviour.StartShooting` requires a target, rolls an integer fire batch in `[fireBatchSizeMin, fireBatchSizeMax)` and clamps it to 0–14, selects the shot type, and rolls one real/fake bit per batch shot using `probabilityOfRealShot`. The effective definition is interpolated and perk-scaled; its precise value must come from trusted army catalog/loadout authority. A zero batch is possible from malformed/unusual source values and must not become a free hit.
4. For ordinary Rusher rifle-family weapons, `PrepareToShoot` starts `ShootStand` and delays `Shoot` by 30% of the weapon's standing-shot animation length; flamethrower uses zero delay. SWAT weapons use the shield-uncover length. `Shoot` schedules `ShootJustStarted`, then `ShootingFromWeapon` invokes `SoldierBehaviour.Shooting` while the shooting state and life remain valid. The latter checks `currentWeapon.willShoot`; a secondary weapon fires once and switches back after 0.5 seconds. Other batches choose real or deliberately offset fake rounds, call `OnShot`, and end after the batch count.
5. `EndShooting` clears both shooting flags. `ReturnToPreviousStateFromShot` replaces the Rusher cooldown with `mTime + Random.Range(2f, 4f)`, overriding the generic `minShootTime/maxShootTime` roll. Retarget timing pauses while a shot is pending. Death, cover departure, target loss, retarget, and match end must cancel or invalidate pending host shot work before it can deal damage.

The army deployment artifact pins the five serialized base shot fields for all six scene-backed `SoldierBehaviourRusher<T>` families, and the runtime catalog composes normal, special, and elite source rows before applying trusted perk accuracy. The version-eleven Rusher weapon artifact additionally pins the exact normal scene inventory, runtime weapon type, handedness, both enemy-rig gun snaps, each family's windup and cadence rules, Commando poison provenance, and Shotgunner walking-fire provenance: zero ticks for Flamethrower, nine ticks for ordinary one-second stand-shoot clips, and 30 ticks for SWAT's one-second `shield_unhide`. Each clip path, clip digest, serialized legacy length, cadence source path, and source digest is part of the combat revision. Runtime cadence is strict: base Soldier weapons use 0.35 seconds/11 ticks, Paratrooper uses 0.25/8, and Commando plus Warper use 0.2/7. `ArmyRusherAttackState` owns eligible -> windup -> ordered batch -> cooldown, including real/fake rolls, weapon cadence, and the source 30 Hz timing domain. After a batch, it uses the Rusher-specific 2-4 second cooldown from `ReturnToPreviousStateFromShot` rather than the generic upgrade-row shoot time.

Match-owned Rusher state creates bounded shot intents only after moving-target and post-arrival gates pass. At `PrepareToShoot`, it copies the current Moving target position into a match-owned batch latch, reuses that exact position for every shot in the batch, and pauses the 1.5-second inactive-cover retarget clock while the attack is in windup or firing. Batch completion clears the latch, a committed retarget replaces it only after no shot is pending, and entity death removes it. Projectile-backed families advance entity-owned flight against current recovered player poses, validate impacts, apply player health through the shared damage kernel, and publish shot/impact events. Flamethrower owns its separate six-pulse overlap path. No client packet chooses real/fake bits, target, damage, windup, or cooldown.

Paratrooper activates kevlar only for a selected special lane. The recovered `Kevlar` component creates a second pool equal to `composed SPECIAL × unit max health`; each hit first reaches the unit, then its original damage is refunded up to remaining kevlar and charged to that pool, so excess spills into health exactly once. The host now owns both pools, applies that ordering to host-only army damage, validates the ratio and arithmetic, and projects current/maximum kevlar in reconnect pages. `SoldierBehaviourParachuter.cs` and `Kevlar.cs` are source-hashed in combat revision nine.

SWAT `UpdateVisual` applies its mobility special only when `controller.hasSpecial`: runtime movement speed is multiplied by `1 + soldierBehaviourDefinititon.special`. The host now composes that value from the selected normal/special/elite rows, requires an actual special-lane selection, applies the trusted perk coefficient in the same multiplicative chain, and validates the result before allocation and spawn. The source file and formula are part of combat revision eight.

Shotgunner and Warper use `BulletShotGun`, whose recovered prefabs set a three-unit radius, flat-Y cone comparison, and `shotOnlyMainBullet=true`. Each behavior replaces serialized max/min damage at runtime with composed unit damage and ten percent of that value. The host therefore computes `min + (max - min) * (1 - clamp(3D distance / 3))` from its muzzle to the latched batch target at launch, retains that immutable damage with the projectile, and applies a ten-percent floor at or beyond three units. This corrects the prior generic full-damage treatment; the visual fake-trail fill has no damage authority.

When Shotgunner's special lane is selected, `ApplyWeaponsSetup` enables shooting while running and divides both composed walking-shot intervals by composed `SPECIAL`. The host now schedules that initial walking cooldown once, permits a batch only while the unit is still walking with more than one unit of route remaining, uses the recovered 0.35-second walking windup, and continues advancing the unit during windup and firing. A deterministic match test observes a real shot intent while the motion phase remains `Walking` and proves route progress continues across the shot tick. Arrival waits for any pending walking batch, then restores the ordinary Rusher attack and its recovered 2-4 second post-batch cooldown. Moving animation, muzzle sampling, and Client effects remain presentation work.

The five-second constant, behavior assignment, coroutine arithmetic, and wait interval are source-hashed in the combat revision.
