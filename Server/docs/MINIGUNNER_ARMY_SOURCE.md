# Minigunner army source boundary

The recovered 1.4.0 `MainScene` binds `ID_UNIT-MINIGUNNER` to `SoldierBehaviourMinigunner`, behavior component file ID 41873 and upgrade component file ID 45363. Its serialized base definition supplies probability 1, a one-to-four-shot batch, a two-to-five-second ordinary cooldown, speed 0.9 and projectile speed 5. The normal scene inventory resolves to `MiniGun.prefab`, runtime weapon type 4, one `MiniGun/HK416/MachinegunMuzzleFlash` origin, the recovered one-second `shield_unhide` windup, and the subclass's strict 0.17-second cadence (six 30 Hz ticks). These values and their source hashes are now part of the combat revision.

The original APK assembly itself declares `UpgradeSlotsMinigunner : UpgradeSlotsBaseSoldier<DBUpgradeSlotsShotgunner>`. This is not an AssetRipper spelling error: direct IL decompilation of `Clients/AuxiliaryFiles/GameAssemblies/Assembly-CSharp.dll` yields the same closed generic type. The method then requests `ShieldRechargeRate`, although the recovered `DBUpgradeSlotsShotgunner` schema has no such column and the separate 60-row `DBUpgradeSlotsMinigunner` table is not the generic argument. The server therefore preserves the actual Shotgunner stage binding for stat composition and keeps the Minigunner shield ability closed. Substituting the unused Minigunner table would invent behavior that the 1.4.0 executable does not select.

The live host constructs a stationary attack state when a Minigunner spawn becomes authoritative. It reproduces `SwitchStateToMinigunner`'s initial random 2–4.5-second delay, the one-second `shield_unhide` windup, the serialized one-to-four-shot batch, strict six-tick cadence, and the ordinary composed 2–5-second post-batch cooldown. Each real shot uses the pinned MiniGun rest muzzle and speed-5 `BulletSlow` flight. Collision begins 0.1 units in front of the visual muzzle, matching `BulletSlow.Fire`; map geometry, live shields, and player hitboxes remain authoritative along the remaining path.

Army-card Minigunners call `PickPlayerOpponent(1f)`. `GameShootableEntityPlayer` replaces its serialized type-2 child with the current cover shield's `shotPosition`, so the host latches that cover target for each batch. A projectile that reaches an opposing live shield applies the recovered `UnitToShieldCoef` value of 3 through the shield lifecycle and publishes the normal shield damage or destruction event. Source geometry is not bypassed: the deterministic Park deployment strikes the intervening stand, exercising a real map impact rather than granting damage through cover. The live test proves spawn, initial delay, windup, shot publication, forward-offset physical flight, and impact; the shield kernel separately proves the pinned army damage coefficient.

The source's later 6–10-second random point-change branch and the broken Minigunner shield upgrade remain outside this slice. General stationary-unit retarget behavior still needs its own source-backed host transition. The unprovable shield row must not grant extra health or recharge authority.
