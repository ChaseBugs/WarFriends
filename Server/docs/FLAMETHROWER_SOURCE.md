# Army flamethrower source contract

The recovered 1.4.0 flamethrower is an infantry weapon on `SoldierBehaviourFlamethrower`, not a player inventory weapon. `WeaponFlamethrower` has weapon type 12, a serialized 0.5-second cadence, infinite ammunition, and no reload. Each real shot creates one `FlameAmmo` instance. The ammo performs exactly six independent overlap checks after strict 0.35-second intervals, then expires.

Each pulse queries a radius of 3 around the weapon spawn point. It ignores the owning side, ignores a collider-center distance below 0.3, flattens only the weapon's forward Y coordinate, and accepts an enemy when its center angle is strictly below `Lerp(60, 40, Pow(distance, 0.25))`. Damage uses `Lerp(effectiveDamage * 0.1 / 6, effectiveDamage / 6, 1 - distance / 3)`. The recovered behavior overwrites the prefab's serialized 8/30 damage values with these effective-unit values.

`ArmyFlameBurst` owns the six host pulse deadlines. At the fixed 30 Hz server clock, the source strict-greater-than test makes each interval eleven ticks, at offsets 11, 22, 33, 44, 55, and 66. `ArmyRusherAttackState` separately enforces the weapon's 15-tick cadence between shots in one batch. The validated unit-upgrade catalog reads `REALSHOTPROBABILITY`, `BATCHSIZEMIN/MAX`, and `SHOTFREQUENCYMIN/MAX` from every recovered army stage and composes the selected normal, special, and elite lanes exactly as `UpgradeSlotsBaseSoldier.LoadData` adds them. Flamethrower stage zero therefore schedules probability 0.8, batch 1/1, and cooldown 2.3-3.0 seconds instead of its serialized prefab fallback. MatchEngine samples the current opposing animated collision model for every pulse, applies Flame damage through the common player authority, publishes shot/impact events, accounts each live burst under the global projectile limit, and aborts the unscored match if trusted collision or damage authority is damaged.

The focused `--flame-only` suite covers all pulse deadlines, the six-pulse terminal state, center-distance damage, minimum range, cone rejection, malformed authority, and batch cadence; the combat-content suite covers normal/special upgrade-row composition. The focused `--rusher-only` test now admits two real UDP peers, deploys a source Flamethrower, observes host navigation, and requires an `army-flame` shot, pulse impact, and authoritative opponent health loss. This also corrected the shared Rusher intent contract to carry distinct owner and target player IDs; the earlier single-ID shape caused every live army shot to be discarded at its ownership gate. The combat manifest now pins the enemy rig gun-snap chain and every serialized Rusher weapon spawn-point chain. The host composes the flamethrower rest-pose muzzle offset and rotates it with authoritative target-facing instead of emitting pulses from the army root. Shoot-animation bone motion still needs a Unity-sampled pose export. Accuracy perks, unit visual/effect projection, shield/barrel targets, and normal Client presentation remain part of B14/B32.
