# Rifle cover and first-shot sequencing

`RifleCoverTimeline` implements the default rifle branch's playback instructions from recovered `PlayerController.PlayShotAnimation` and `SoldierAnimationController.ShotFromCover`. It resolves the two side inversions, starts uncover at speed four with a 0.02-second cross-fade, queues the firing clip, restarts an already-playing firing clip, and reverses an interrupted hide using `1 - hide.normalizedTime`. Repeated requests extend the strict 0.4-second hide deadline. Hide begins at the observed host update after that deadline; it emits a direct Play instruction followed by CrossFadeQueued idle.

The timeline provides clip times, explicit transition/queue instructions and outgoing/incoming layers for the hide-to-idle blend. The queued idle starts 0.3 seconds before hide completion; its clock carries that elapsed time into full idle instead of restarting at zero. The pose catalog evaluates these layers, but the live Worker does not yet consume them or reproduce every queue/interruption case in Unity's mixer. Consumers must preserve these semantics before using it to authorize geometry. The existing pose artifact binds source clip durations and wrap behavior; this code currently supports the default rifle family at time scale one, not every weapon animation variant.

The timeline now also retains the outgoing layers during the 0.02-second uncover fade. `PlayerPoseCatalog.SampleLayers` evaluates those weighted local transforms into a combined collision/muzzle pose. Interrupted hide-to-idle fades can retain both outgoing layers while introducing the new uncover clip. Mixing is bounded to four layers; exceeding that bound rejects the transition before changing timeline state. This is an explicit reconstruction bound, not a recovered Client limit. General queued-clone identity and every interruption sequence still need actual Unity playback coverage.

`RiflePlaybackTests` exercises the integrated source path: playback layers -> blended pose -> placed AK47 muzzle -> source-bound BulletSlow projectile -> opponent hitbox -> health kernel. The victim is sampled during hide-to-idle blending. This isolated test has no map geometry and uses a fixture health manifest; it does not prove profile/loadout allocation, live Worker command ordering, Client presentation or settlement.

`RifleFirstShot` ports the scheduling portion of `PlayerClickWeapon.Sh` and its delayed Update branch. Idle starts wait for one quarter of uncover length; a same-side interrupted hide uses the recovered hiding-time calculation; walking after stopping uses 0.05 seconds. Side changes override the wait with one quarter of uncover length. The saved target remains unchanged while waiting. Equality does not fire: the source checks strictly greater than the deadline. A clicked player defers the pending attempt, and changing weapon selection cancels it. A cover move keeps a pending shot; it resets the stopped-shooting flag for the next walking click. Successful reload and empty-ammo paths also reset that flag. The replacement command stream does not yet represent every mouse-held `clicked` frame, so precise click-duration deferral remains part of normal input integration.

The source may call Fire immediately from an existing firing/running state and also schedule a delayed attempt when the side changes. This is retained deliberately. The authoritative weapon must recheck cadence, ammunition, reload and eligibility for each attempt; scheduling is not an ammo debit or damage event. Button release/autofire gates, aiming-angle checks, weapon ownership and network command ordering remain caller responsibilities and are not yet connected to these classes.

Tests cover side mapping, uncover/queue timing, hide deadline equality, interrupted-hide reversal, repeat requests, saved aim, clicked deferral, cancellation, the immediate-plus-delayed case, walking waits and malformed clocks. Worker integration and complete source-rig mixer comparison remain outstanding; these tests do not establish full gameplay validation.

## Unity queue measurement

`SelfHostedAnimationQueueAudit.Run` creates an empty scene in the disposable project, enters actual Play Mode and runs an isolated legacy Animation component at a captured 30 Hz. A synthetic half-second hide clip animates one bone from X=0 to X=1; queued idle holds X=10. The artifact `unity-animation-queue-reference.json` records 38 observed frames with enabled states, state clocks, weights and the actual animated position. No game scene or prefab is saved. Run without `-quit`; set `WAR_ANIMATION_QUEUE_OUTPUT`. The audit exits Unity after writing the results.

The observed queued clone enables at 0.2 seconds with zero weight, then blends linearly over 0.3 seconds. At 0.5 seconds, idle's clock is already 0.3 seconds. `QueuedCrossFade` matches all observed incoming clocks/weights and linear bone positions. This corrects the earlier nominal timeline's late-starting idle clock. Short outgoing clips, interrupted mixes, rotation blending and source-rig queue execution still require further evidence. The helper explicitly rejects outgoing clips shorter than the fade rather than inventing their scheduling.

Validation: isolated Play Mode probe passed; 9,975 Battle assertions passed including 114 queue-reference comparisons. This is a real Unity animation test, not a two-client battle test.
