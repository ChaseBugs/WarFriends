# Projectile lifecycle continuation

`BulletFlight` ports the real `BulletSlow` normal-time-scale path and its `fast` branch, together with `BulletBase.AnimateShot`. It runs under a trusted collision resolver at the host's 30 Hz tick rate. A public packet cannot provide a collision, damage amount, player target identity or resolver.

The normal branch caps the initial target displacement to 50 units and offsets its initial ray by 0.1. Static hits (source layers 13/30) retain their impact until travel completes. Dynamic hits are not treated as guaranteed hits: the initial animation stops `checkDistance` short while retaining the full travel duration, then the host rechecks traveled segments using the source distance-plus-`2*deltaTime` rule. An absent target enters the source follow-through/checking and final miss travel stages. The fast branch selects a hit at launch, optionally predicts its position using target velocity and `distance/speed + 0.1`, and still defers impact until travel completes.

`MatchEngine.ConfigureProjectiles` binds a trusted preparation function before participant admission. Accepted commands create at most one projectile, retain existing command retry receipts and debit ammunition once. Each match admits at most 128 live projectiles; exhaustion rejects the shot without consuming ammo. Every tick is required while projectiles are active. Finished flights are removed before impact application, and terminal outcomes clear remaining flights. Valid player impacts feed the previously implemented source damage/refund/death path. Invalid host geometry or damage authority aborts the unscored match rather than granting an outcome from damaged state.

The finite 10,000-unit replacement for source infinite ray queries and 1,800-second segment bound are explicit host resource policy. Simulation uses normal time scale; fake shots are presentation, and the distinct `ignoreTimeScale` path is not silently mapped here. Grenades/rockets/physical ammunition, area effects and shotgun selection are separate pending variants. Source frame ordering versus Unity's tween callback order still needs temporal comparison beyond the source-derived tests.

The opt-in `unscored-rifle-combat` Worker now installs this binding using the pinned rifle definitions, animated muzzles, source bullet masks, host-owned critical rolls and dynamic player hitboxes. Tests connect actual MatchEngine Fire commands through a trusted fixture resolver and verify delayed health loss/death, moving-away misses, fast prediction, retries, resource limits, malformed inputs and terminal cleanup. Other weapon classes remain closed; no arbitrary client-reported hits were introduced.

Track the complete remaining scope in [BattleServer features](BATTLE_SERVER_FEATURES.md), especially B02/B04/B06/B07/B08/B28/B32. These tests do not certify the entire projectile family or a rendered two-client battle.

Validation on 2026-09-19: final Battle run passed 2,071 assertions (poll-dependent total); solution build passed with zero warnings/errors; 1,017 protocol and 44 native Mongo/HTTP/UDP checks passed. Source-derived tests cover slow rechecks, fast prediction/delay, misses, exact-once impact emission, Fire retry conservation, delayed match health/death, capacity, invalid target handling and corrupted damage authority.
