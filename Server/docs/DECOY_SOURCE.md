# Decoy source boundary

The recovered `CardDecoy` consumes one card and starts a coroutine that creates exactly three `Decoy` objects. For each object it rebuilds the list of free `EnemyPointObstacle` rows owned by the card faction, chooses one with Unity's random range, samples that obstacle's initial midpoint against NavMesh area mask 1 within radius 10, and reserves the slot in `Decoy.Setup`. A Decoy death releases its exact obstacle slot. If no slot is free, the Client waits 0.2 real-time seconds and retries; the server will reject activation before consumption unless three slots can be reserved atomically, rather than creating a partially authoritative card effect.

[`recovered-decoy-source.json`](../content/recovered-decoy-source.json) pins all 89 obstacle rows referenced by the five multiplayer `EnemyPointsCollection` components: Aztec 17, City 19, Desert 20, Park 13, and Snow 20. Every row retains collection order, component/GameObject identity, faction, endpoint-transform identities, source endpoints, and the exact initial midpoint created by `EnemyPointObstacle.Awake`. The artifact also pins the `Decoy.prefab` digest, its single Body target at local `(0, 0.431, 0)`, its enabled non-trigger BoxCollider, the source spawn count of three, and `CardConstants.DecoyHpMin=62.5`/`DecoyHpMax=1090`.

`DecoySourceCatalog` validates the complete schema, artifact and scene hashes, exact map/faction counts, ordered unique identities, midpoint derivation, prefab graph, collider geometry, and constants. It reproduces the source health interpolation `Lerp(62.5, 1090, playerLevel / maxDisplayLevel)` and selects three distinct free same-faction slots with host-owned randomness. Fewer than three free rows leaves activation unavailable. Run `python Server/tools/extract_decoy_source.py --check` after changing recovered scenes, the prefab, or source content.

The Worker now exposes authenticated `UseDecoyCommand` activation after the card is selected. It reserves one server-owned `CardDecoy`, chooses three free same-faction slots with host randomness, samples their midpoints against the pinned NavMesh within radius 10, faces them toward the average opposing defend-position shot target, and commits all three entities or none. Request receipts prevent a second command ID from consuming or spawning the same activation again. Each entity retains its source obstacle identity, level-scaled health, facing, position, and owner in `BattleDecoyState`; spawn/destruction events and owner cleanup release the exact obstacle reservation. The portable SDK validates these rows and exposes `UseDecoyAsync`.

The Decoy collider participates in the shared player-projectile trace as a typed opposing dynamic target. Trusted projectile damage changes host health, credits confirmed enemy hits, and lethal damage removes the entity and frees its slot. Humvee automatic targeting now checks live opposing Decoys before UnitType-3 `AttackerRusher` entities and player fallback, retains the source full projectile speed for Decoys, and requires the selected Decoy to remain visible when the host starts the attack. The trusted Backend allocation now provisions one isolated activation count for each selected player/card pair when the Worker registers the match; one participant cannot spend the other's card. A deterministic live Humvee-versus-Decoy match proves Decoy-first selection, full projectile speed, typed collision damage, destruction events, and exact obstacle release. Normal Unity Client presentation is still required for the complete playable path.
