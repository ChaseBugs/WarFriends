# Land Mine source boundary

The recovered `CardLandmine` filters `SpawningManager.enemyPoints` to opposing `EnemyPointType.Hiding` rows, selects at most three distinct rows with Unity randomness, and samples each selected GameObject transform against NavMesh area mask 1 within radius 10. This differs from Decoy placement: Land Mine uses the obstacle GameObject transform, while Decoy uses `EnemyPointObstacle.position`, the midpoint of its endpoints.

[`recovered-landmine-source.json`](../content/recovered-landmine-source.json) pins all 89 Hiding rows referenced by the five multiplayer `EnemyPointsCollection` components: Aztec 17, City 19, Desert 20, Park 13, and Snow 20. Every row retains collection order, component/GameObject/transform identity, faction, source transform position, and map digest. It also pins both identical MainScene player Mine setups, the `MineAmmo.prefab` mesh and trigger geometry, the three-target limit, NavMesh inputs, `LandMineDamageMin=62.5`, `LandMineDamageMax=1090`, the card's 0.1 damage scale, the source 0.9 player-radius coefficient, and the recovered radius/explosion fields.

`LandMineSourceCatalog` validates the complete artifact as part of combat package version 7 in both the Backend allocator and Worker. It reproduces the card damage expression `(Lerp(62.5, 1090, playerLevel / maxDisplayLevel) * 0.1)` and selects up to three distinct opposing slots with host-owned randomness. Malformed vectors, changed scene/prefab identities, incomplete maps, mismatched faction counts, unknown fields, or a stale digest stop package loading. Run `python Server/tools/extract_landmine_source.py --check` after changing the recovered scenes, Mine prefab, constants, or extraction logic.

`MatchEngine` now accepts authenticated, idempotent Land Mine activation only for a selected `CardLandmine`, reserves the server-owned card inventory, chooses the opposing source slots, samples their positions against the authoritative NavMesh, and atomically publishes one to three mines. `LandMineMatchRegistry` bounds active rows, prevents partial placement, retains request receipts for replay, and supports owner cleanup. Protobuf snapshots and lifecycle events expose ordered mine identity, source slot, placement, owner, and source-scaled damage; the portable SDK validates that projection and provides the typed activation call.

The authoritative tick now tests the recovered trigger box against current oriented player and non-metal infantry collider volumes. An opposing overlap atomically consumes the mine, emits `LandMineTriggered`, and applies the source 0.9-scaled dead/hurt radius to nearby player and opposing infantry poses through the existing health, death, statistics, and terminal-result kernels. The implementation uses the recovered fact that `CardLandmine` assigns the same value to `damageAmount` and `explodeDamageAmount`, so the radius branch changes Explosion/Shiver type while preserving raw damage. The same triggered blast queries the host's live scene colliders at the unscaled 1.8-unit hurt radius. Source `MissileExplode` uses nearest collider bounds for the inner/outer branch; the host routes shield hits through the explosion coefficient and friendly-fire policy and barrel hits through the existing ordered chain authority. A Park host match seeds a mine at the opposing player's cover, triggers it, and verifies the nearby source shield loses health and advances revision alongside player damage. A separate Snow host match moves a player along the recovered cover path, triggers a mine near scene barrel 182, and verifies exactly ten barrel HP lost, the revision increment, mine consumption, and a `BarrelDamaged` event on the second bounded event page.

The normal recovered `CardManager` path now sends `UseLandMine` instead of running the Photon card implementation, and consumes the card only after an accepted host response. `SelfHostedLandMinePresenter` reconciles authoritative snapshots with script-free copies of the recovered `MineAmmo.prefab` mesh, removes them on the trigger event or snapshot disappearance, and plays the recovered big-explosion particle/sound presentation without invoking local damage. A Unity 2018.3 render audit proves mesh identity, authoritative placement, absence of Photon/gameplay scripts and colliders, event removal, and snapshot reconciliation.

The same host-triggered blast now checks deployed ground-vehicle body colliders. Recovered `MissileExplode` selects one part per multipart damage root by closest world bounds; the host chooses one placed body part in that order, applies its serialized weight without the bullet-only 0.33 armor coefficient, and uses the MainScene `FriendDamageCoeficient` for an allied vehicle. A deployed Humvee host test proves one opposing hit, half-damage allied hit, and agreement between Army vitality and vehicle-registry health. This test invokes the host blast transition at a source collider; natural mine-triggered vehicle contact still needs proof.
