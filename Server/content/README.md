# Recovered battle evidence

`local-rifle-match-template.json` is the reviewed local matchmaking template generated from the same pinned City map, AK-47 stage zero, opposing main covers, and player-damage values exercised by `LiveRifleTests`. Regenerate it with:

```powershell
dotnet run --project Server/tests/War.Battle.Tests/War.Battle.Tests.csproj -c Release -- --write-rifle-template Server/content/local-rifle-match-template.json
```

The generator validates the manifest and recovered combat allocation before writing. Backend matchmaking replaces only match/player identities and trusted Mongo allocation projections; the Worker validates the resulting complete manifest again.

`recovered-player-poses.json` contains initialized single-clip samples for the gameplay player: 32 clips, 490 frames and 2,940 Unity collider-ray comparisons across all four recovered assault-rifle cover/run animation families. Clip assets retain their own source hashes and original names. See [player poses](../docs/PLAYER_POSES.md) for sampling and animation-blending boundaries.

`recovered-player-collision.json` separately records the two MainScene player rigs in their serialized reference pose, four primitive hit parts and 32 Unity collider-ray comparisons. See [player collision](../docs/PLAYER_COLLISION.md) for initialization and animation limitations. It is not a ready-to-use animated combat rig.

`recovered-battle-content.json` is exported from the active WarFriends 1.4.0 recovered Client by `SelfHostedBattleExport.Run`. It contains five multiplayer scenes, world-space covers and navigation paths, collider geometry, reference Physics rays and MainScene Google2u rows. Source scene paths and SHA-256 digests are embedded.

The exporter runs in Unity and does not save scenes. Set `WAR_BATTLE_CONTENT_OUTPUT` to an absolute output filename. Use a disposable project; do not export from scenes with unsaved edits. The current export was produced with Unity 2018.3.0f2, the repaired workspace environment, not the original APK build environment.

The server validates map geometry before use. The eleven assault-rifle, nine shotgun, eight SMG, six pistol, eight burst-LMG and dedicated minigun families have validated immutable combat catalogs; other source sheet rows are not yet validated combat catalogs. Battle content must not authorize purchases or rewards. Serialized shield health is a base value. Movement speed, player health, loadout upgrades and damage coefficients must be bound from their complete source contracts before scored combat is enabled.

`recovered-rifle-bindings.json` records eleven MainScene assault-rifle setup/inventory/controller/BulletSlow bindings and reference muzzle positions. Export with `SelfHostedWeaponExport.Run` and `WAR_WEAPON_OUTPUT`. `RifleBindingCatalog` binds this artifact to the rifle-stat and scene revisions. Reference muzzles are not animated combat poses; see [rifle stats and bindings](../docs/RIFLE_STATS.md).

Map identity is the source scene filename and digest: several scenes share the serialized `MapDefinition.levelName` value. Do not merge them on that value. Paths retain the source cover indices; they are not freely traversable player coordinates. Static raycasts ignore triggers and inactive/disabled colliders; shield collider suppression is live in rank-bound matches, while other destructible-state changes remain pending.

Run `dotnet run --project Server/tests/War.Battle.Tests` to validate the five maps and compare 200 exported Physics rays. See [Battle Server status](../docs/BATTLE_SERVER.md) for the remaining implementation work.

`unity-animation-queue-reference.json` is an isolated Unity Play Mode measurement of legacy `CrossFadeQueued` timing and linear bone blending, generated by `SelfHostedAnimationQueueAudit.Run`. It is test evidence, not gameplay content. See [rifle cover sequencing](../docs/RIFLE_COVER.md) for its limits.

`recovered-rig-blend-reference.json` records nine Unity blends of the 142-transform gameplay hierarchy. The pose artifact also includes that hierarchy's local transforms in every sampled frame. See [rig blending](../docs/RIG_BLENDING.md) for validation and remaining runtime integration.

`recovered-barrel-scene-bindings.json` maps all 29 multiplayer barrel colliders to exact Unity GameObject, collider, Barrel and DestroyableObject file IDs plus their serialized shot coefficients. Generate it with `python Tools/Extract-BarrelSceneBindings.py` from the repository root; the extractor verifies the five scene hashes and rejects ambiguous objects. The Worker validates the resulting map at startup. Barrel damage remains a host-only lifecycle kernel until ownership and explosion behavior are integrated; see [dynamic entities](../docs/DYNAMIC_ENTITIES.md).

`unity-barrel-overlap-reference.json` is an isolated Unity 2018 Editor audit of `Physics.OverlapSphere` at every multiplayer barrel center for both recovered explosion radii. The source script is `Server/tools/UnityBarrelOverlapAudit.cs`; copy it into a disposable project's `Assets/Editor`, set `WAR_BARREL_OVERLAP_OUTPUT`, and call `WarBarrelOverlapAudit.Run` in batch mode. It does not save scenes. The Battle test suite checks all five scene hashes and compares every selected destroyable collider with the server's source-indexed candidates. Its raw target order was identical in two fresh Unity runs and is pinned by `BarrelOverlapRevision` for the host's fixed scene-barrel chain planner. It does not establish arbitrary or moving target order.

`unity-player-explosion-overlap-reference.json` is the corresponding Unity 2018 geometry audit of the initialized gameplay rig's two hit parts across nine idle/firing/running source poses and 180 explosion-radius probes. Its script is `Server/tools/UnityPlayerExplosionOverlapAudit.cs`. The Battle test suite binds it to MainScene and checks every collider result against `PlayerHitbox.OverlapsSphere`. It proves those primitive-overlap cases, not complete player explosion damage.

`combat-content-manifest.json` pins scene, stats, rifle binding, pose, barrel binding, barrel overlap, army deployment/spawn/Rusher points and PlayerPoint world positions, serialized player shot targets, five scene-bound NavMesh binaries, their Unity-exported triangulations, and 432 Unity path fixtures for Worker startup. `recovered-player-shot-targets.json` preserves the two MainScene player target lists in source order; its static reference positions do not replace animated hit transforms. `navmesh/` contains exact recovered Unity binary copies, `navmesh-triangulation/` contains 9,658 source walkable triangles, and `navmesh-path-results/` retains 416 complete and 16 partial Unity paths. Their manifests bind source identities and hashes. The host planner now produces planar-covered candidate corners but does not move army units. A separate comparison fixture, `recovered-navmesh-motion.json` plus eight files in `navmesh-motion/`, pins 2,863 observed Unity Play Mode infantry frames across the five maps and all three stock ground-infantry speeds; the host candidate now reaches the City detour in the sampled trace. See [combat content configuration](../docs/COMBAT_CONTENT.md) and [navigation evidence](../docs/NAVMESH_SOURCE.md). This package validates allocations; it does not establish player ownership or complete source navigation behavior.

`recovered-shotgun-bindings.json` is a read-only Unity export of the nine MainScene shotgun inventory/setup/weapon/pellet bindings, generated by `SelfHostedShotgunExport.Run` with `WAR_SHOTGUN_OUTPUT`. `shotgun-content-manifest.json` pins it to the scene and upgrade-sheet revisions. `ShotgunCatalog` validates all nine bindings and 464 stages. This separate package feeds opt-in live, unscored shotgun matches; see [shotgun source](../docs/SHOTGUN_SOURCE.md).

`recovered-smg-bindings.json` is the corresponding read-only export for all eight `PlayerBurstWeapon` SMGs, generated by `SelfHostedSmgExport.Run` with `WAR_SMG_OUTPUT`. `smg-content-manifest.json` pins the export and recovered upgrade sheets. `SmgCatalog` validates all 398 stages plus inventory, animation, muzzle, projectile, burst, speed and mask authority. It feeds live unscored burst simulation and mixed loadouts; see [SMG source](../docs/SMG_SOURCE.md).

`recovered-pistol-bindings.json` is the Unity export for all six `PlayerClickWeapon` pistols. `pistol-content-manifest.json` pins 306 stages and the scene bindings used by live unscored pistol and mixed combat; see [pistol source](../docs/PISTOL_SOURCE.md).

`recovered-lmg-bindings.json` and `lmg-content-manifest.json` pin the eight non-minigun LMG families and 398 stages used by live unscored two-round burst combat; see [LMG source](../docs/LMG_SOURCE.md).

`recovered-minigun-binding.json` and `minigun-content-manifest.json` pin the separate 36-stage, finite-pool, non-reloadable minigun contract. The checked-in binding is derived from the pinned all-weapon export plus exact serialized MainScene controller/weapon values; `SelfHostedMinigunExport.Run` is the read-only Unity re-export path once the disposable Editor is available. See [minigun source](../docs/MINIGUN_SOURCE.md).

`recovered-sniper-bindings.json` is the read-only MainScene export for all eight `PlayerZoomOnTouchWeapon` families. `sniper-content-manifest.json` pins it to all 428 recovered upgrade rows. See [sniper source](../docs/SNIPER_SOURCE.md).

`recovered-bazooka-bindings.json` is the read-only MainScene export for all seven `PlayerHoldWeapon` bazooka families. `bazooka-content-manifest.json` pins it to all 412 recovered upgrade rows, including M202's secondary muzzle, curved trajectory, four-shot schedule and fake/real pattern. See [bazooka source](../docs/BAZOOKA_SOURCE.md).

`recovered-grenade-bindings.json` is the read-only MainScene export for the M320 launcher and seven `PlayerSwipeWeapon` grenade families. `recovered-grenade-poses.json` adds 289 Unity samples across 12 grenade/launcher clips, including the shared left-hand spawn omitted from the rifle rig. `grenade-content-manifest.json` pins both artifacts plus all 398 recovered upgrade stages, exact swipe-strength bounds, ballistic setup, explosion coefficients and projectile identities. `GrenadeCatalog`, `GrenadeThrowPlanner`, `GrenadeFlight`, and `GrenadeExplosion` validate this deployment input; grenade match admission remains closed until its MatchEngine and Client presentation paths are connected. See [grenade source](../docs/GRENADE_SOURCE.md).

- `recovered-all-weapon-bindings.json`: Unity-exported identity/component/projectile graph for all 66 recovered player weapon families; pinned by the combat manifest and validated at Worker startup.

`recovered-ground-vehicle-weapons.json` is the version-7 extracted graph for four runtime ground-vehicle prefabs. It binds turret and projectile paths, all source body colliders, six passenger seats, the Transporter mini-drone prefab, root hit collider, and both seven-point repair paths, and the companion passenger-pose revision. `recovered-vehicle-passenger-poses.json` contains Unity-sampled `idle` and `buggy_idle` body/head collision geometry from the recovered enemy prefab. The Worker validates both artifacts together before admitting combat.
